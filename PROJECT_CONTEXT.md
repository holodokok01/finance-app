# Финансы: Telegram Mini App. Контекст проекта и задача миграции на React

Прочитай этот файл целиком перед любой работой. Рядом лежит `legacy/index.html`: рабочее приложение в одном файле (около 4700 строк, 520 КБ, ванильный JS без сборки). Это эталон поведения и вида. Задача: перенести его на React без потери функций и без визуальных отличий.

## 0. Как работать с владельцем

- Владелец, Митрофан, дизайнер. Смотрит результат только на iPhone (Telegram и Safari). Отвечай по-русски, коротко, без длинных тире. Пиши «модал», а не «модалка».
- Только целые числа в размерах, отступах и позициях: никаких 0.5px, 5.97px.
- Перед дизайн-решениями показывай 2–4 варианта визуально и давай рекомендацию с причиной. Названия простые и по роли, не абстрактные.
- Если что-то неясно, задай короткий вопрос с вариантами ответа, а не гадай.
- Перед созданием или изменением файлов проекта сначала покажи план, строй после его «ок».
- После каждой правки тестируй: headless Chrome с эмуляцией iPhone (390×844, DPR 2, touch, locale ru-RU), Playwright, `/usr/bin/google-chrome` с `--no-sandbox`. Реальные свайпы и зажатия делай через CDP `Input.dispatchTouchEvent`. Честно говори, что проверено только в эмуляции: ощущение от свайпов, хаптику, Safari и Telegram владелец проверяет на телефоне.
- Перед большими правками делай бэкап.

## 1. Что за приложение

Личный трекер финансов в формате Telegram Mini App (открывается из бота внутри Telegram). Один пользователь, данные хранятся у него: localStorage и Telegram CloudStorage. Бэкенда нет. Приложение мобильное, только портрет, мини-экран 390×844 как эталон. Языки: украинский, русский, английский. Валюты: основная настраивается (по умолчанию EUR), конвертер работает с 150+ валютами.

### Экраны (нижний таб-бар из 4 вкладок)
1. **Главная.** Верхняя панель с большими squircle-углами: баланс, подпись «Свободно X €» (баланс минус обязательные платежи до конца месяца, показывается только если есть платежи), кнопки Расход, Доход, Скан (Скан пока заглушка). Карточки доходов и расходов за 30 дней. Ниже карточки: «Операции» (раскрывается в полный список, который «вырастает» из карточки, закрывается свайпом вниз), «Платежи» (три ближайших, в день оплаты кнопка «Оплатил» создаёт операцию и двигает дату), «Баланс в валютах».
2. **Статистика.** Переключатель Расходы/Доходы (пилюля с меню), период Неделя/Месяц/Год, свайп по полосе месяцев (лента едет за пальцем как picker, быстрый флик пролетает несколько периодов), кольцо из капсул-сегментов с анимацией, сумма в центре (подгоняется под размер кольца), список категорий со сравнением с предыдущим периодом, прогноз и доли, столбики по дням, лист операций категории или диапазона.
3. **Конвертер.** Список валют, любая строка может быть вводом, своя клавиатура, добавление валюты через шит с поиском, режим правки (удаление и перетаскивание), свайп строки для удаления.
4. **Настройки.** Учёт: основная валюта, категории, обязательные платежи. Данные: экспорт и импорт CSV, демо-история, очистить всё. Приложение: тема (Система, Тёмная, Светлая; табы с иконками), язык (UA, RU, EN), вибрация.

### Модалы и шиты
Добавление операции (сумма со своей клавиатурой, категория, заметка, дата через собственный календарь), инфо операции (редактирование, удаление), менеджер категорий, редактор категории (название, 20 цветов, иконка Solar или эмодзи), выбор иконки, обязательные платежи (шит со строкой «В месяц» и цветной полоской, список, пустой экран по центру), редактор платежа (сумма со своей мигающей кареткой, название, дата через календарь который смотрит вперёд, период, категория), выбор валюты, фильтры и поиск по операциям, undo-тост после удаления.

### Единые паттерны жестов (повторяются везде, делай их общими хуками)
- **Удаление в списках:** короткий свайп влево показывает корзину, длинный удаляет при отпускании.
- **Удаление в модалах:** кнопку «Удалить» нужно зажать на 0,9 с (заполняется прогресс), короткий тап показывает тост «Зажми, чтобы удалить».
- **Перетаскивание порядка** (конвертер, категории): строка поднимается, едет за пальцем, остальные расступаются.
- **Закрытие шита:** потянуть вниз (только если скролл внутри в самом верху).
- **Press feedback:** нажатый элемент уменьшается и пружинит обратно.
- **Сегмент-контролы:** одна пилюля плавно едет к активной кнопке с резиновым отскоком.
- Блокировка скролла страницы под открытыми шитами. Высота шитов следует реальной высоте viewport (она может измениться сразу после первого открытия, особенно в iOS webview).

## 2. Стиль

Тёмный минимализм в стиле Framer, плюс полноценная светлая тема.
- Акцент `#0099ff`, доход `#30d158`, ошибки и удаление `#ff453a`. Шрифт SF Pro (system stack). Иконки Solar Bold (набор `ICONSET` в файле, объект `имя -> svg path`, лицензия CC BY 4.0, указана в коде).
- Скруглённые углы **squircle** (сглаживание 100%, та же математика, что в figma-squircle, свои радиусы по углам). В исходнике элемент получает `data-sq data-r="24"`, скрипт считает путь и ставит `clip-path`; рамка 1px делается слоем `--edge` под внутренним слоем `--fill`. В React сделай компонент `<Squircle r={24}>` с ResizeObserver, повторным измерением после загрузки и после шрифтов. Тени на такой элемент не работают (clip-path), тень вешается на обёртку через `filter: drop-shadow`.
- **Нижний таб-бар «liquid glass» утверждён, не менять.** Переноси CSS и разметку 1в1 (блок `/* Tab bar: liquid glass */` и переменные `--tb-*`).
- Темы: CSS-переменные в `:root` (тёмная) и `:root[data-theme="light"]`. Переменные: `--bg --panel --raise --line --text --text-2 --text-3 --seg --press --dline --grab --dash --pop --line2 --rim --tb-* --tint-*`. Атрибут `data-theme` всегда выставлен явно (`dark` или `light`). Режим «Система» следует за Telegram (`WebApp.colorScheme`, событие `themeChanged`) и за `prefers-color-scheme`. Функции `themeCalc()` и `themeApply()`; при смене тема также красит шапку и фон Telegram и `meta theme-color`.
- **Ловушка светлой темы:** `--raise` равен `--bg` (`#f2f2f7`), поэтому любой элемент, который лежит на сером фоне страницы и красится через `--raise`, невидим. Для таких элементов (пилюля Расходы, трек периода, кнопки конвертера) в светлой теме используется `--panel` (белый), активный таб `--bg`. Элементы внутри белых карточек остаются на `--raise`. Не хардкодь тёмные цвета, всё через переменные.
- Все размеры целые px. Числа в UI: суммы с пробелом-разделителем тысяч (неразрывный пробел), центы мелким серым шрифтом (`.cents`), символ валюты слева для EUR/USD и справа для остальных (`preSym()` и `postSym()`).

## 3. Данные и хранение

**Ключи localStorage:** `fin_v1` (операции, категории, платежи, основная валюта, стартовый баланс), `set_v1` (настройки), `cv_v1` (список валют конвертера), `rx_v1` (кэш курсов: `{date, r}`).

**`fin_v1`** (строка JSON, сохраняется с задержкой 300 мс, функция `saveSoon()`/`saveNow()`):
```
{
  at: number,                 // Date.now() последнего сохранения, по нему выбирается свежая копия (облако или локальная)
  base: "EUR",                // основная валюта
  opening: 6000,              // стартовый баланс
  cats: { order: { expense: [id...], income: [id...] },
          items: { [id]: { n?, ru?, icon?, emoji?, color, type: "expense"|"income" } } },
  pays: [ { id: "p...", sum: number>0, cat, n?: string, per: "week"|"month"|"year", next: ts, day?: number } ],
  tx:   [ { ts: number(полночь дня), t: "HH:MM", cat, sum: number(<0 расход, >0 доход), note: string, demo?: 1 } ]
}
```
- При загрузке для каждой операции считаются `d` (дней назад от сегодня) и `id`. Операции с неизвестной категорией отбрасываются. Старое поле `title` мигрирует в `note`.
- Категория: `n` это своё имя пользователя, `ru` это ключ перевода встроенной категории; отображаемое имя `n || L(ru)`. Встроенные: Продукты, Транспорт, Кафе, Жильё, Досуг, Здоровье и др. (расходы), Зарплата, Фриланс (доходы).
- Баланс: `opening + доходы - расходы`, операции с `demo` не считаются.
- **`set_v1`:** `{ base, haptic, demoOff, opening, theme: "system"|"dark"|"light", lang: "uk"|"ru"|"en" }`.
- **Telegram CloudStorage:** весь JSON режется на куски по 3000 символов: ключи `fin_v1_n` (число кусков) и `fin_v1_0..N`. При старте облако читается, и если его `at` новее локального, оно применяется. Сохраняй совместимость формата: у владельца уже есть данные.
- **Демо-история:** функция `addDemoHistory()` добавляет операции за прошлые месяцы с флагом `demo`, чтобы стрелки периодов в статистике было на чём показать. Выключается переключателем в настройках (`demoOff`).
- **CSV экспорт и импорт:** формат нашего CSV (те же колонки), при импорте неизвестные категории пропускаются, дубликаты не добавляются. Экспорт через «Поделиться» там, где устройство позволяет, иначе копирование текста.
- **Курсы валют:** открытый API `@fawazahmed0/currency-api` (две зеркала: jsdelivr и pages.dev), кэш на день, встроенные примерные курсы `RX_FALLBACK` на случай офлайна. Ответ приходит относительно EUR.
- **Обязательные платежи:** `payAdvance` сдвигает дату (неделя +7 дней; месяц и год с учётом длины месяца и `day`), `payMonthly` приводит всё к «в месяц» (неделя ×52/12, год ÷12), `payFree` считает «Свободно» симуляцией оплат до конца месяца, `payDo` («Оплатил») создаёт операцию на сегодня.

## 4. Переводы

Словари `I18N.uk` и `I18N.en`. **Ключ это русская строка**, функция `L(ru, params)` ищет перевод, подстановки `{n}`, `{v}`. Для русского возвращается сам ключ. Множественные числа через `plural(n, "день", "дня", "дней")` и таблицу `PLW`. Новые строки добавляются через `Object.assign(I18N.uk, {...})`. Язык по умолчанию определяется из Telegram или браузера (`detectLang()`). Языки в интерфейсе подписаны кодами UA, RU, EN (порядок в списке: uk, ru, en). Подписывать русский словом «русский» не нужно, владелец из Украины и этого не хочет.

## 5. Интеграции

- **Telegram WebApp SDK** подключается только внутри Telegram (приходит `tgWebAppData` в hash), чтобы вне Telegram ничего внешнего не блокировало загрузку. Используется: тема и цвета шапки, CloudStorage, нативная хаптика.
- **Хаптика:** в Telegram нативная (`HapticFeedback`), вне него фолбэк через скрытый iOS 18 `<input type="checkbox" switch>`, который «тикает». Включается настройкой «Вибрация».
- Ориентация: в ландшафте (`max-height: 500px`) показывается экран «поверни телефон» (`.land`). Хостинг даст возможность блокировать поворот через Telegram.
- Нет роутера: вкладки переключаются без URL, шиты это оверлеи поверх.

## 6. Карта исходника (где что искать в `legacy/index.html`)

Секции размечены комментариями `/* ---------- ... ---------- */`. Ориентиры: Squircle (~1029), Telegram и Haptics (~1125), Data и ICONSET (~1177), Languages (~1226), Saving (~1345), Filters и Search (~1454), Full list (~1661), Exchange rates (~1815), Transaction details (~1882), Add operation sheet (~2048), Date picker (~2338), Tab bar (~2390), Undo (~2485), Statistics (~2512, кольцо ~2587, свайп месяцев ~2975), Converter (~3254), Settings (~3727, экспорт ~3786, импорт ~3815), Categories (~3876), Recurring payments (~4421). CSS занимает первые ~1000 строк. Перед переносом экрана прочитай его блок целиком, не угадывай.

## 7. Недавно исправленное (учти при переносе)

- Сумма в центре кольца статистики: функция `paintEurFit` уменьшает шрифт целыми px (с 34px, центы пропорционально, минимум 16px), пока ширина не станет не больше 148px. Это нужно для сумм от 10 000 €. Повтори логику в React-компоненте.
- Светлая тема, контролы на сером фоне: см. «Ловушку светлой темы» выше. Исправлено на главной, статистике, конвертере, настройках.

## 8. Что проверено и что нет (светлая тема)

Проверено: главная, статистика, настройки, модал добавления, платежи, конвертер (основной экран). Не проверено: менеджер и редактор категорий, выбор иконки, инфо операции, календарь, выбор валюты. При переносе этих экранов сразу делай их в светлой теме через переменные.

## 9. Дорожная карта продукта (после миграции)

1. Хостинг на GitHub Pages и бот через BotFather: даст живые курсы, облако Telegram, экспорт через «Поделиться» и блокировку поворота.
2. **Скан чека:** фото, распознавание через Gemini (бесплатный уровень, ключ только на сервере, никогда в клиенте; запасной вариант Tesseract.js), предзаполненная операция, одна волна в стиле Distortion Waves, когда результат готов. Сейчас кнопка Скан это заглушка.
3. Проверить на iPhone моргание текста «Год» в табах «Период» редактора платежа (исправлено вслепую через `translateZ`).

## 10. Задача: перенос на React

**Цель:** то же приложение на React + TypeScript, результат визуально и по поведению неотличим от `legacy/index.html`, данные пользователя совместимы (те же ключи и формат из раздела 3).

**Рекомендуемый стек (подтверди с владельцем перед стартом):** Vite, React 18, TypeScript, один легковесный стор (Zustand), CSS без CSS-in-JS (перенести существующие стили и переменные как есть, модульно по экранам), без UI-библиотек. Сборка должна давать статику для GitHub Pages.

**Порядок работы:**
1. Покажи владельцу план: структуру папок, список компонентов и хуков, порядок экранов. Жди «ок».
2. Основа: токены и темы (CSS-переменные, `themeApply`), `Squircle`, иконки (вынеси `ICONSET` из HTML в отдельный модуль или JSON, не держи 100+ КБ в компоненте), i18n (`L`, `plural`), слой хранения (`fin_v1`, `set_v1`, CloudStorage с чанками, миграции), курсы валют, Telegram и хаптика.
3. Общие хуки жестов: `useSwipeRow` (короткий и длинный свайп), `useHoldToDelete` (0,9 с), `useReorder`, `usePullToClose`, `usePressFeedback`, `SegmentedControl` с едущей пилюлей. Сначала они, потому что на них держатся почти все экраны.
4. Экраны по одному в таком порядке: таб-бар (копия 1в1) и каркас, главная, добавление операции и календарь, инфо операции, статистика, конвертер, настройки, категории, платежи.
5. После каждого экрана: сравнение скриншотов с `legacy/index.html` в обеих темах (390×844, DPR 2), проверка жестов через CDP, отчёт владельцу что проверено в эмуляции, а что ему надо глянуть на телефоне.

**Критерии готовности экрана:** пиксель в пиксель с эталоном в обеих темах; все жесты работают; данные из старого приложения (JSON из `fin_v1`) открываются без потерь; нет жёстко прописанных цветов, всё через переменные; целые px; `tsc` и сборка без ошибок.

**Чего не делать:** не менять дизайн и тексты «заодно», не трогать таб-бар, не добавлять зависимости без согласования, не терять демо-историю и экспорт/импорт CSV, не вписывать ключи API в клиент.
